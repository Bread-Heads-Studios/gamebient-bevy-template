## Open: fleet audit 2026-09-23 — app-lifetime clock reads

Dive Rise's production `UNVERIFIED` was `Time<Fixed>::elapsed()` read from
nine sim systems: it counts from **app** start, so a run forked on how long
the player sat in the menu, while the verifier always re-simulates at offset
zero. Fixed in dive-rise#5 and folded into the template (rule 7,
`sim::RunClock`, the `record_windowed_after_menu` row and a
`tools/rollout-replay.sh` advisory).

**Every verified game still needs auditing for the same read.**

Many are presentation/juice systems and harmless. The ones that **look like

`pack-the-ripper/{sorting,conveyor}.rs`, `sundae-shooter/launcher.rs`.

**Dive Rise itself is the one game that diverges.** It shipped the fix first,
as `run::RunClock(pub f32)` in its own `src/game/run.rs` with
`run::sync_run_clock`; the template's is `sim::RunClock { secs, ticks }` in
the verbatim-copied `sim.rs`. Its next `--upgrade` will therefore hand it a
*second*, unused clock and a duplicate source-scan test. Converge it then:
point the nine systems at `sim::RunClock.secs`, delete `run::RunClock`,
`run::sync_run_clock` and `run::tests::no_app_lifetime_clock_in_sim_code`,
and keep `sim::sync_run_clock` second in the chain. Bit-neutral either way —
both restate the same number from the same tick index.

Per game: run `tools/rollout-replay.sh --upgrade` to pick up `sim::RunClock`
and the new probe, read every hit the advisory names, replace the sim ones
with `RunClock`, and re-run the after-menu row. **The row only proves
something on a long, busy run** — a 1 720-tick Dive Rise run that ate
nothing verified green on the broken build at eight different clock offsets.
Note that this invalidates the wave-0/1/2 production proofs only if a hit
turns out to be in a sim system; the proof runs themselves were short.

## Wave-2 lessons (2026-09-18)

Three wave-2 ports, three findings general enough to expect again. The
script and checklist changes they produced are in
`tools/rollout-replay.sh` and `port-checklist.md`; what follows is the part
that is about *ports*, not about tooling.

**Attic Excavator — the board seed, and what must NOT move onto `GameRng`.**
`level::board_seed` drew from `rand::rng()`, so the board itself was
non-reproducible and no replay of a real run could ever have verified; it now
draws from `sim::GameRng::next_u64()` with `begin_run` chained ahead of
`setup_level`. The mirror-image judgement is more interesting: `treasure.rs`'s
random toy name became a **pure function of the cell** rather than a
`GameRng` draw. Moving presentation randomness onto the sim stream is the
actual bug — the windowed build would consume a draw the verifier does not,
and every later board desynchronises. The rule: a draw may join `GameRng` only
if **both** builds make it, the same number of times, in the same order.
Particles kept `rand::rng()` behind `allow-forbidden-rng` for the same reason.
Its probe also could not reach the interactions its two `SpawnOrder` sorts
guard (the fixture bot routes around heavy junk and sleeping cats), so the
dependency is written down as two targeted unit tests instead, with the
measurement recorded in the game's `docs/replay-notes.md` so nobody reads the
green probe as evidence the sorts can go.

**Pack The Ripper — animation-named systems that belong in `SimSet`.**
`animate_punch`, `animate_reveal` and `animate_fling` write only
`Transform.scale`/`rotation`, which nothing folds — but each *removes a
component from, or despawns,* an entity the sim queries. The insert side was
already in the chain, so leaving the removal in `Update` would hold packs in
different archetypes in the two apps. It is the archetype, not the value, that
decides: read what a system inserts, removes and despawns, not what it is
called. Second, on fixtures: the selftest's misgrade indices count **grading
presses** and must stay below the number the run actually makes (two at 20 and
45, against 58 at the committed seed). An index past the end is never reached
and nothing fails — the first draft lost a whole Collector Trust of coverage
exactly that way. Re-tuning the ramp or the mash cadence means re-recording
both fixtures.

**Sundae Shooter — the sim was reading `ScreenFade`.** See "The third trap"
under rule 1 in `port-checklist.md`; `tests/windowed_shape.rs` is the
regression, and it is now copied into every game by the rollout script.

## Fleet upgrade lessons (2026-09-18, template d806aa0)

All six ported games were pulled forward to template `d806aa0` and adopted
`tests/windowed_shape.rs` in one pass (the PR numbers are in the status
table). Every probe came back green on `src/` as it stood — no game was
found reading presentation state — so what the pass produced is knowledge
about the *probe*, not about the sims. Four findings, each already folded
back into the template:

**A careful fixture bot under-tests the probe.** This is the big one.
Attic Excavator measured it: over the selftest script's full 1800 ticks
`heavy::wobble_shake` fired **zero** times and `cat::cat_touch` never
connected, because that game's fixture router costs +60 for a cell under
heavy junk and +25 near an awake cat — it avoids by construction exactly the
two windowed-vs-headless divergences worth probing. Two planted bugs (a
*sim* system filtering its query `With<Visibility>`; the checksum folding the
`translation.x` only `wobble_shake` writes) **passed** under the fixture bot
and **failed** only under a second, heavy-seeking one. A probe that never
runs the system it is probing is green for the wrong reason. The template's
probe now ships a two-row bot table with `reckless_script` as a documented
placeholder in the second row, and the checklist's rule 1 has the step:
measure (a counter resource per windowed-only system), and if the fixture bot
is a careful router, write a reckless second script and assert it reaches
them.

**`Option<Res<GameAssets>>` is the biggest resource fork in a real game.**
`ScreenFade` is the trap that shipped, but it is one resource; assets are
where a mid-sized game's two builds actually diverge. Attic Excavator has
nine systems in and around the sim chain taking `Option<Res<GameAssets>>` and
taking the `Some` branch in the browser and the `None` branch in the
verifier, and everything hangs off it: meshes, materials, `Visibility`,
children, backdrops, floating labels, overlays, particle debris. Enumerate
those first when extending `record_windowed` — the fade is the cheap part.

**Carrying `AssetsPlugin` into the probe needs hand-made asset stores.**
`build_headless_app` is `MinimalPlugins` and has no `AssetPlugin`, so a
game's `AssetsPlugin` cannot bake its `GameAssets` there. Insert the stores
it draws from before adding it:

```rust
app.insert_resource(Assets::<Mesh>::default());
app.insert_resource(Assets::<StandardMaterial>::default());
app.add_plugins(AssetsPlugin);
```

That is what lets systems taking a non-`Option` `Res<GameAssets>` (Attic
Excavator's `cat::update_cat_look`) be in the probe at all. Cannonball Putt
is the counter-example and equally worth knowing: its `GameAssets` could not
be carried this way, and what its presence changes there is hole geometry
that `archetype_order`'s faithful mode already materialises — so it was
documented as a deliberate gap rather than faked.

**`toggle_pause` is a tolerated fade read, not a finding.** The template's
`FixedUpdate` pause toggler takes `Option<Res<ScreenFade>>` and refuses a
pause while the fade is busy — the Sundae Shooter shape exactly — and four
ported games carry it verbatim. It is safe only because rule 8 masks
`Buttons::PAUSE` in both `replay::recorder` and `replay::feeder`, so
`pause_just_pressed` is false on every tick of every replay and the fade's
answer is never reached. Written up in the checklist's rule 1 ("The two
tolerated reads") and in the template's own `toggle_pause`; the rollout
script's fade advisory now recognises the shape by its `pause_just_pressed`
edge rather than by the template's name, so it stops firing on every upgrade
of every game.

**CI drift is real and silent.** Two of the six upgrades added the `Cutter
tests` step by hand and the other four did not, leaving games shipping
`tools/test_cut_clips.py` with a green CI that never ran it.
`rollout-replay.sh` now inserts that step (first rollout and `--upgrade`,
guarded on the file being present, idempotent). Expect the same class of
drift elsewhere: `--upgrade`'s workflow diff advisory is the thing that
surfaces it.

## Wave-3 lessons (2026-09-22)

Four ports — Gulper, Ladder Legend, Grand Theft Otto, Dive Rise — and the
first wave in which the *contract* moved rather than only the tooling. Each
finding is written up where a porter will meet it (`port-checklist.md`,
`docs/replay-verification.md`, `tests/windowed_shape.rs`); this is the
index.

**The transcendental rule — never fold what libm produced.** Rule 5 gained
its one exception. Gulper folded `head.facing`
(`velocity.y.atan2(velocity.x)`) and one 5400-tick fixture gave three
verifiers three answers with identical score and ticks: macOS, the Linux CI
runner and wasm. That is not an informational mismatch — `cargo test`'s
`committed_fixture_still_verifies` re-simulates the committed *native*
fixture *natively*, so the job went red on a machine that was not the
porter's. Bisected: ticks 1–7 bit-identical, parting at tick 8. Two halves,
both cheap: **fold no libm result bit-exactly** (it is almost always a pure
function of something folded beside it), and **make a transcendental whose
argument is constant under the fixed tick a literal** — Gulper's
`(-EEL_DRAG * dt).exp()` became `DRAG_PER_TICK`, Dive Rise turned eight
such decays into `*_PER_TICK` constants. Unit-test each literal against the
tick length with a `1e-6` tolerance, never bit-exactly: a bit-exact
assertion pins the porter's own libm, which is the dependency the literal
removes. Measured bit-neutral on Dive Rise. `rollout-replay.sh` now greps
`src/game/` for the five calls and prints a HAND EDIT (advisory) pointing at
the rule; `test_rollout_replay.sh` part (s) covers it.

**What stays is a real limit on where a run may be recorded.** A
varying-argument transcendental (a wander phase, a drift angle) has no
literal to write and can still reach a folded number sideways. Dive Rise's
rendered run parts from Node at tick **44 083** — twelve sim-minutes —
three ticks after a hunter bite folds a `sin`/`cos`-driven hunter position
into the player's knockback; Sundae Shooter's parts at **1056**. So: **only
a wasm-recorded run is guaranteed to verify.** Production is safe (browser
records in wasm, site re-simulates in wasm), and a *native*-recorded run —
a cabinet run above all — may legitimately fail. Verified leaderboards
accepting cabinet submissions is an open question, not a solved one.

**The third trap is wider than "resources".** Dive Rise's
`swim_burst::dash` fell back on `Transform.scale.x.signum()` for the
direction of a dash thrown with no stick held — and that sign is written by
an `AssetsPlugin` `Update` system mirroring the sprite, so it is `+1` for
ever in the verifier. A dash from a standstill while facing left went
opposite ways in the two builds, 0.4667 m, and never re-converged; it fired
several times a run, because taking a draft card *is* A-with-no-stick. All
three probes were green for their own reasons: the fixtures run bare (both
sides read `+1`), `archetype_order` adds components but never writes an
existing one's *value*, and `windowed_shape` carried resources and left the
decorators out. The rule is now **a sim system may not read any state the
windowed build writes and the verifier does not**, resource or component
field; the fix is to latch the thing from `TickInput` into sim-owned state
and let presentation *paint* it. The probe now carries the real
`AssetsPlugin` on hand-made stores (`AssetPlugin` + `init_asset` for
`Shader`/`Mesh`/`ColorMaterial`/`StandardMaterial`) — the stronger version
of the wave-2 `insert_resource(Assets::<T>::default())` note below, and the
one to use, because a plugin that *loads* anything needs an `AssetServer`.

**And a third bot row, because two were structurally not enough.** With
`AssetsPlugin` carried and both shipped bots, Dive Rise's probe still
passed: the forager faced right on all six of its blind dashes and the
diver held `DOWN` every tick so its stick was never zero. The shipped rows
hold a direction on *every* tick, so between them they never produce an
idle-stick tick — and a "do it the way you're facing" fallback fires on
exactly those. The template now ships `coaster_script` (hold LEFT 90 ticks,
release 30, tap A during the release) as the third row. Mutation-checked on
the template itself: a planted `tf.scale.x.signum()` in `move_player`
passes all three rows alone (the template's `AssetsPlugin` is a stub), and
fails the coaster row — and only it — as soon as that plugin is given the
`face_movement` system every real game has.

**A run may not leave `Playing`.** Gulper bounced `Playing → Digest →
Playing` once per band, so `begin_run`/`begin_recording`/`seal_run` fired
per band and the verifier stopped at the first chasm — and the tuning
screen, the biggest single influence on the rest of a run, was an `Update`
system on `GameInput` and was not recorded at all. Dive Rise's draft was
the same shape and worse: the verifier builds no `UiPlugin`, so a draft
opened there would never close. The fix in both: delete the state, make the
phase a **sim resource** driven by `TickInput` inside `SimSet` (Gulper
`run::RunPhase`, Dive Rise's opening shop). A resource and not `SubStates`,
because `NextState` applies once per *frame*. Count the presentation cost
honestly — a `ScreenFade` wipe drives *state* changes, so Gulper's hunt →
tuning transition is a hard cut now; re-add it as a presentation-only
reaction to the phase change, never by routing the phase back through
`GameState`.

**Input outside the canon is unreplayable.** Ladder Legend's
`input::read_input` probed `Query<&Gamepad>` for the four face buttons
because the canon folds South/North into `A` and cannot express a dance-mat
panel — so a run played on the platform's *canonical* controller for that
game recorded lane steps no verifier could reconstruct. Bridge it:
`input::mat_panel_bridge` latches the panels onto `VirtualInput` as
ordinary direction bits in `PreUpdate` `.before(accumulate_input)`, after
which the sim reads no raw input at all. Same game, second half: **a dev
autopilot must end its runs through input.** `drive_autopilot` pinned
`data.health = 0.0` to finish its tour, which makes any recording through
it unverifiable; it now lets missed notes drain HP through the real
game-over path, and that is what made a verified autopilot tour possible.

**Attract mode: register the same functions twice.** Grand Theft Otto's
title screen sits over a living city, and four systems ran in `Menu` as
well as `Playing` behind a custom `scene_live` run condition. All four
write run state the sim reads and two draw from `GameRng`, so none could
stay in `Update` for `Playing`. Resolution: the same four functions
registered **twice** — inside `sim::SimSet` for `Playing`, and in `Update`
gated on `Menu` **alone** for attract mode. Safe only because
`sim::begin_run` reseeds `GameRng` and rewinds `SpawnCounter` on
`OnEnter(Playing)`; pair it with an `OnExit(Menu)` cleanup so no attract
entity survives into the run.

**And the probe's blind spots keep being about what the runs do.** All four
games reported sorts that their `archetype_order` probe could not reach
(Gulper 3, Grand Theft Otto 2, Ladder Legend 1, Dive Rise 1) — two walkers
replanning on one tick, two predators in biting range at once, two morsels
eaten on one tick, an exact timing tie — because the events the sorts order
never occurred under the fixture bot. Attic Excavator's remedy still
applies and was used: a targeted unit test, plus a paragraph in the game's
`docs/replay-notes.md` so nobody reads the green probe as licence to delete
the sort. Dive Rise's `eat_food` is the one that shipped with the argument
written down and no test; it is the wave's known soft spot.

## Game over, autopilot, input

All games end a run from a `Playing`-gated gameplay system via
`fade.request(GameState::GameOver)` (e.g. Gulper `death.rs:97`, Voidrunner
`collision.rs:269,371`, Cannonball Putt `hole_flow.rs:66`, BeerPong
`scoring.rs:108`) **except Dough.io**, which calls
`next_state.set(GameState::GameOver)` directly (`eating.rs:282`) — see
`references/irregular-games.md`.

Every game has an autopilot; 9 write `GameData` fields directly for
screenshots (dev-only, allowed, but keep that code path out of the
selftest script per rule in `port-checklist.md`): attic-excavator
(`autopilot.rs:213-218`), cannonball-putt (`:378`), dough-io (`:308`),
grand-theft-auto-reply (`:240`), ladder-legend (`:227`), pizza-pinball
(`:268,273`), sundae-shooter (`:197`), tire-stack (`:184`), voidrunner
(`:307-308`). pack-the-ripper's autopilot is read-only.

This section is the 2026-09-16 survey as it stood; ported games have moved
on. Ladder Legend's autopilot no longer pins `health = 0.0` — it ends its
tour through the real game-over path, which is what let the port record a
verifiable autopilot run (see the wave-3 lessons), and every ported game
now ends its run through `sim::end_run` rather than a bare fade request.
